# Мой книжный год

Русскоязычный PWA-трекер чтения для телефона с входом через Google и синхронизацией библиотеки в Supabase. Без подключённого проекта доступен локальный режим. Интерфейс рассчитан на экраны 320–430 px: одна колонка, постоянная нижняя навигация, крупные сенсорные кнопки, формы с размером текста 16 px и учётом безопасных зон экрана. На компьютере сохраняется телефонная компоновка шириной до 480 px. React, TypeScript, Vite, Tailwind CSS, Lucide, Recharts, date-fns, Dexie / IndexedDB и vite-plugin-pwa. Для облачного режима нужен настроенный проект Supabase; свой сервер разрабатывать не требуется.

## Подключение аккаунта

Пошаговая настройка Supabase, SQL-миграции, Google OAuth и переменных окружения описана в [SUPABASE_SETUP.md](SUPABASE_SETUP.md). Без этих настроек Google-вход отключён, а локальные данные доступны как раньше. JSON-экспорт сохранён как дополнительная резервная копия.

## Запуск

Нужен Node.js 22.12+ или 24 LTS и npm.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173). Для обычной работы используйте один и тот же адрес браузера: разные адреса, порты и профили имеют отдельные хранилища.

## Проверки и production

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`dist/` — готовая production-версия. Preview обычно доступен на http://127.0.0.1:4173. Service worker включён в production-сборке; в dev-режиме офлайн-кеширование намеренно отключено.

Браузерные проверки:

```sh
npx playwright test
```

Тесты используют установленный Google Chrome (`channel: chrome`), временные профили и production-сборку. Перед ними выполните `npm run build`. Они проверяют создание книги, прогресс, долги, календарь, завершение, IndexedDB после перезагрузки, JSON, мобильную навигацию и офлайн-перезагрузку с записью чтения. Другой Chromium-браузер можно указать в `playwright.config.ts`.

## Размещение на HTTPS

1. Выполните `npm ci` и `npm run build`.
2. Загрузите **содержимое** `dist/` на статический HTTPS-хостинг в корень отдельного домена или поддомена. Команда сборки для CI — `npm run build`, выходная папка — `dist`.
3. Убедитесь, что `/manifest.webmanifest`, `/sw.js`, иконки и `/assets/*` доступны без авторизации с правильными MIME-типами. Для `sw.js` задайте `Cache-Control: no-cache`; для файлов с хешами в `/assets/` допустим длительный кеш.
4. Откройте сайт с интернетом и дождитесь регистрации service worker. После первой полной загрузки приложение работает без сети, включая сохранение прогресса и перезагрузку.

Приложение настроено на корень сайта (`/`), а не на подпапку. Для подпапки нужно согласованно изменить `base`, `start_url`, пути иконок и fallback в `vite.config.ts`.

HTTPS обязателен для установки и service worker на внешнем домене. `localhost` и loopback-адреса на собственном компьютере являются исключением. Адрес `http://192.168.*` с телефона не заменяет HTTPS: для проверки установки на Android используйте HTTPS-размещение.

## Установка

**Windows / macOS:** откройте production-сайт в поддерживающем установку браузере. В «Настройках» нажмите «Установить приложение», когда эта функция доступна. Также можно использовать значок установки в адресной строке или пункт установки в меню браузера. Приложение откроется в отдельном окне.

**Android:** откройте HTTPS-сайт в Chrome → меню ⋮ → «Добавить на главный экран» → «Установить». Либо используйте кнопку установки в настройках приложения, когда её предложит браузер.

**iPhone / iPad:** Safari → «Поделиться» → «На экран Домой».

Доступность кнопки зависит от браузера и того, установлено ли приложение. Фактический системный диалог установки на физических Windows/macOS/Android-устройствах не автоматизируется тестами. Manifest содержит обычные PNG-иконки 192×192, 512×512 и отдельную maskable-иконку 512×512 с безопасными полями.

## Использование

- Добавьте книгу в пять коротких шагов: название, объём, режим, отдых, подтверждение плана. Автор и обложка необязательны. Изображения PNG/JPEG/WebP/GIF до 3 МБ сохраняются локально.
- Выберите страницы или главы, автоматическое распределение до даты либо фиксированный темп. Для новой книги срок по умолчанию — 31 декабря. Книги можно отложить на полку «Хочу прочитать» или приостановить.
- «Отметить прочитанное» записывает **количество за сессию**, а не номер последней страницы. Для прошедшего дня выберите дату в календаре или в форме записи.
- В календаре доступны месяц, неделя, фильтр книги и разовые дни отдыха. Чтение в выходной разрешено, обязательного задания нет.
- Откройте «Посмотреть план»: там есть все дневные задания, неоплаченные даты и история сессий. После завершения история остаётся доступной в библиотеке и годовых целях.
- Год выбирается в верхней панели. «Цели на год» открываются через карточку годовой цели, в том числе на мобильном экране «Сегодня». Настроить число книг можно также в «Настройках».

## Как устроены расчёты

`src/engine.ts` содержит чистые функции планирования, распределения целых единиц, зачёта фактического чтения, долгов, прогноза и серии.

План создаётся не раньше текущей даты и даты начала книги. Указание более раннего начала при добавлении новой книги само по себе не создаёт ретроспективных долгов. Первоначально прочитанный объём хранится отдельно: он увеличивает общий прогресс, но не выдаётся за ежедневные сессии.

Задания за прошедшие дни сохраняются. При изменении режима, нормы, дедлайна или выходных пересчитываются сегодняшние и будущие задания. Прошедший отдых не отменяет уже возникший долг. При паузе будущие задания удаляются, а прошлые остаются; возобновление строит будущий план с текущего дня.

Фактический объём последовательно оплачивает самые ранние задания. Избыток — это кредит для будущих заданий. Поэтому он не учитывается второй раз при наступлении следующего дня. Сумма непогашенного исторического и будущего плана равна оставшемуся объёму (при наличии доступного будущего расписания). В плане показаны исходное задание и его непогашенная часть; их не нужно складывать. Долг — только непогашенная часть дат строго раньше сегодняшней.

При нуле доступных дней мастер просит изменить срок или выходные. Все вычисления используют локальные календарные даты `yyyy-MM-dd`, календарное прибавление дней, без деления суток в миллисекундах для расписаний.

После появления записей или прошедших заданий общий объём, начальный прогресс и единица книги фиксируются, чтобы не смешивать страницы с главами и не менять смысл сохранённых долгов. Режим, норма и дедлайн остаются редактируемыми.

Достижение полного фактического объёма автоматически завершает книгу, сохраняет дату и обновляет годовую цель. Ручное подтверждение завершения явно записывает остаток как прочитанный сегодня. Завершённая книга засчитывается в год фактического окончания (`completedAt`), даже если её планировали на другой год. Например, книга с планом на 2026 год, законченная в январе 2027, учитывается только в цели 2027 года. Правило применяется также к ранее сохранённым книгам и резервным копиям. Незавершённые книги остаются в выбранном году плана. Отдельного увеличиваемого счётчика нет. Статистика страниц и глав относится к датам фактических сессий чтения.

Прогноз для фиксированного темпа использует выбранную норму и выходные. Для автоматического плана после появления сессий используется средний объём за дни с чтением; до этого — план. Прогноз является оценкой. Серия пропускает регулярные и разовые выходные, если это отдых для всех соответствующих книг. Статистика страниц и глав разделена.

## Данные и резервное копирование

Без входа книги и настройки хранятся в IndexedDB (`my-book-year`) в текущем браузере. После входа каждая учётная запись получает отдельный локальный кеш и облачную библиотеку в Supabase. В аккаунт синхронизируются книги, изображения, задания, записи чтения и настройки. При недоступной сети изменения сохраняются локально и отправляются после восстановления соединения; статус виден в настройках.

«Настройки» → «Экспорт JSON» сохраняет полную резервную копию. «Импорт JSON» проверяет версию, типы, даты, объёмы и уникальность идентификаторов, затем просит подтвердить **замену** текущей библиотеки. Перед восстановлением экспортируйте текущую библиотеку. Удаление книги также требует подтверждения.

Очистка данных сайта, приватный режим, удаление профиля или решение браузера освободить место могут удалить локальные записи. Регулярный экспорт — способ сохранить и перенести библиотеку. При конфликте изменений между устройствами приложение предлагает скачать копии и выбрать версию вместо автоматического перезаписывания. После выхода приватные данные аккаунта не показываются в гостевой библиотеке.

## Структура

- `src/App.tsx` — навигация, экраны, календарь, аналитика, настройки и диалоги.
- `src/components.tsx` — мастер книги, модальные окна, обложки и выходные.
- `src/engine.ts` — независимые алгоритмы чтения.
- `src/db.ts` — IndexedDB, отдельные кеши аккаунтов и проверка резервных копий.
- `src/sync.ts` — очередь синхронизации, версии и разрешение конфликтов.
- `src/cloud.ts` — Supabase и Google OAuth / PKCE.
- `src/use-account-library.ts` — сеанс пользователя и подключение библиотеки к интерфейсу.
- `src/account-panel.tsx` — вход, выход, перенос данных и состояние синхронизации.
- `supabase/migrations/` — схема PostgreSQL, RLS и атомарная запись библиотеки.
- `src/types.ts` — модель данных.
- `src/styles.css` — палитра и адаптивная верстка, уменьшение анимации по системной настройке.
- `tests/` — автоматические тесты расчётов и резервного копирования.
- `e2e/` — проверки пользовательских сценариев в Chrome.
- `public/` — локальные установочные иконки, без внешних ресурсов.
- `vite.config.ts` — сборка, manifest и генерация offline service worker.

Внешние шрифты и сторонние картинки не загружаются. После настройки облачного режима приложение обращается к вашему проекту Supabase; Google используется только для входа.
